# DECISIONS.md — choices made where the spec was silent or conflicted

Each entry: date · milestone · section · decision · why. Newest at the bottom.

## Milestone 0

- **2026-09-03 · M0 · §19 — Repository layout.** Git root is `waterflood-optimizer/`; the importable Python package is `waterflood_app/` laid out exactly as the §19 tree (`ingest`, `prep`, `models`, `optimize`, `outputs`, `workflow`, `validation`, `messaging`, `store`, `api`, `ui`). Paths quoted without a prefix in the build prompt (`validation/synthetic_suite/`, `messaging/condition_map.yaml`, `ui/src/…`, `outputs/templates/`) live under `waterflood_app/`; `docs/`, `tests/`, `config/`, `pyproject.toml`, `CHANGELOG.md` sit at the git root. *Why:* keeps the §19 tree intact while still giving one installable package and one place for tests and config.
- **2026-09-03 · M0 · §2 of prompt — Python version.** The build machine has Python 3.11.9 and no 3.12. Code targets `>=3.11`; CI matrix runs 3.11 and 3.12. Nothing 3.12-only is used. *Why:* unblock the build now; 3.12 remains the deployment target.
- **2026-09-03 · M0 · §16 Tier 1 — Fixture generator physics.** Fixtures are generated by a CRM-forward simulator (Sayarpour et al. 2009 discrete CRMP solution, Atlas "CRMP" tab), not by a finite-difference simulator. *Why:* the acceptance criteria are stated as parameter recovery (f_ij within 10 %, τ within 20 %), which is only well-posed when the truth *is* a CRM parameter set. A 2-D single-phase FD case would need its own procedure to define "true" f_ij (tracer or perturbation runs) and is recorded as a follow-up under `validation/synthetic_suite/README.md` → "Future work". Aquifer, conversions, allocation noise and sectors are layered onto the same forward model as documented in the README.
- **2026-09-03 · M0 · §9 / Atlas CRMP tab — Direction of the Σf_ij constraint.** The Atlas CRMP equation prints `Σ_i f_ij ≤ 1` (sum over injectors for a producer). The mass-conservation constraint used by Sayarpour 2009 and by pywaterflood is `Σ_j f_ij ≤ 1` for each injector (an injector cannot allocate more than 100 % of its water). §9 separately uses the per-producer sum `Σ_i f_ij > 1.15` as the aquifer signature. Fixtures and the engine apply the per-injector constraint and report the per-producer sum as the aquifer diagnostic. *Why:* the two are different quantities; the per-injector one is the physical constraint, the per-producer one is the diagnostic §9 asks for.
- **2026-09-03 · M0 · §16 — Definition of "within 10 %" for f_ij.** Pairs with true f_ij ≥ 0.05: relative error ≤ 10 %. Pairs below 0.05 (barriers / negligible): absolute error ≤ 0.02. τ: relative error ≤ 20 % per producer. *Why:* relative error on near-zero pairs is meaningless; barriers must still be recovered as barriers.
- **2026-09-03 · M0 · §6 — Fixture data schema.** Long format, one row per well per month: `well_id, date, days_on, q_oil, q_water, q_inj, bhp`. Rates are calendar-day rates in bbl/d (monthly volume ÷ days in month); `days_on` is the producing/injecting days; `bhp` is null unless the case includes pressure. Companion tables `coords` (`well_id, x, y`), `category` (`well_id, field, reservoir, block, alloc_factor`), `events`. *Why:* matches the canonical four datasets of §5 and the days-on rule of §6 without inventing extra columns.
- **2026-09-03 · M0 · prompt §3 — Node.js absent on the build machine.** Milestone 4 (React/Vite UI) will need Node 20+; it is not installed. Flagged now so it can be provisioned before Milestone 3 closes.
- **2026-09-03 · M0 · §9 — Correction: what the "Σf_ij > 1.15 aquifer signature" measures.** The earlier entry said the per-producer sum is the aquifer diagnostic. That is wrong: a producer fed by several injectors legitimately has Σ_i f_ij > 1 (in `streak_5x4`, P-3 receives 1.59 with no aquifer). The physical signature of unmodelled support is an *injector* allocating more than 100 % of its water when the fit is unconstrained, equivalently field production exceeding field injection: `apparent_support_ratio = ΣQ/ΣI` in `truth.json` (1.43 for `aquifer_6x9`, ≤ 1 elsewhere). The §9 gate is implemented on that quantity in Milestone 1; the constrained engine keeps Σ_j f_ij ≤ 1 per injector.
- **2026-09-03 · M0 · §8 / Atlas CRMP — Discrete time convention.** Δt_n = t_n − t_{n−1} is the length of the interval that *ends* at grid point n; i(n) is the injection over that interval; q(n) is the rate at t_n. The injection of the interval ending at t_0 is already inside q(0) and contributes nothing later. `month_grid`, `to_matrices` and the forward model all use this convention; the in-house solver (M1) must too.
- **2026-09-03 · M0 · §9 — pywaterflood baseline alignment.** pywaterflood 0.3.4 adds a `(1−e^{−Δt/τ})·f·i(0)` response at the first sample on top of its primary term `gain_p·q(0)·e^{−t/τ_p}`, so its q̂(0) can never equal q(0) with gain_p = 1. Zeroing i(0) in the arrays passed to pywaterflood makes its convolution identical to the Sayarpour recursion above; the acceptance test does this (`tests/test_fixtures.py::_pwf_inputs`). With the alignment the noise-free recovery is exact (errors < 1e-4); without it the worst pair error was 10.4 %.
- **2026-09-03 · M0 · §7 — O_d for sectored fields.** `sectored_60` has O_d = 120/(24+1) = 4.8 for the whole field (fails the gate) and 9.2 per sector (passes). `truth.json` reports `O_d` on the basis the engine is expected to use (per sector, `O_d_basis`) and `O_d_field` for reference. Sectorization (§7) is therefore a hard requirement for this case, not an optimisation.
- **2026-09-03 · M0 · §16 — Aquifer case tuning.** Fetkovich tank parameters (J_aq = 14 bbl/d/psi, p_aq0 = 3400 psi, p_r0 = 3000 psi, c_t·V_r = 4·10⁴ bbl/psi, c_t·V_aq = 2.5·10⁵ bbl/psi) were chosen so the support ratio lands at 1.43 (prompt: "≈ 1.4"); influx declines from 5600 to 3290 bbl/d over 160 months (partial, declining-pressure drive as the Atlas requires for CRMPA).
- **2026-09-03 · M0 · prompt §2 — ruff configuration.** `RUF001/002/003` (ambiguous unicode) are disabled: Greek letters, × and → are the notation the docstrings must use to cite the Atlas equations. Everything else in `E, F, W, I, N, UP, B, ANN, RUF` is enforced; `mypy --strict` is clean.
- **2026-09-03 · M0 · §16 — Noisy-variant baseline.** On `streak_5x4_noise5` pywaterflood's single-start fit reaches R² = 0.895 (noise ceiling ≈ 0.89) with τ within 13 % but one small pair (true f = 0.075) off by 42 %. The M0 test only asserts R² ≥ 0.8; pair-level tolerance on noisy data is a Milestone 1 target for the multi-start in-house solver.

## Milestone 1 — engine core (2026-09-03)

- **M1 · §9 / Atlas CRMP — Primary-depletion term is tied to τ by default.** The Atlas capacitance model writes the initial-state decay as q(t₀)e^{−(t−t₀)/τ}. pywaterflood frees it (gain_p, τ_p). The free form lets a slowly declining external influx (an aquifer) hide in a long τ_p primary term instead of inflating Σf, which silently defeats the §9 "Σf_ij > 1.15 → aquifer" gate (observed on the external `aquifer_9x9` case: flank sums 0.92/0.74 with the free form, 1.34/1.25 with the tied form). Default `solver.free_primary: false`; the free form remains available and is what the in-house-vs-pywaterflood 1 % regression test uses, so like is compared with like.
- **M1 · §9 — Solver strategy: variable projection before gradient descent.** Multi-start L-BFGS-B alone converged to local minima on the external streak case (SSE 1700 vs. 7 at the truth; f_ij errors up to 72 %). For fixed (τ, τ_p) the CRMP model is linear in (f, g_p, J), so the solver now searches τ on a log grid + Nelder–Mead with bounded least squares inside (VarPro), then polishes with the analytic-gradient L-BFGS-B from that solution and from random starts (the ensemble). After this the external streak recovers f_ij within 5 % and τ within 1 %. CRMIP is seeded from the CRMP VarPro solution.
- **M1 · §7 — Injection is never smoothed.** Hampel/MAD is applied to producer liquid only; injection is a control input (a spike is real water) and is only capped at zero. Applied to injection it replaced short shut-ins and re-targets in the external fixtures and corrupted the model input. For producers the filter replaces only *isolated* spikes (deviating from both neighbours) with k = 5 MAD and ≥ 25 % deviation; zero/shut-in steps never enter the statistics (§7 "short shut-ins retained as signal").
- **M1 · §9 — What "Σf_ij > 1.15" measures (supersedes the M0 wording).** Three quantities are computed from a quick two-start CRMP with tied primary, no per-injector coupling and a distance mask (`solver.quick_fit_distance_factor` × median nearest I–P distance): (a) the field support ratio ΣQ/ΣI; (b) the unconstrained per-injector Σ_j f_ij; (c) the per-producer apparent Σ_i f_ij. The influx gate is (a) > 1.15 **or** max(b) > 1.15 — an injector "delivering" more than it injects is the physical signature. (c) is informational: producers above 1.15 and 1.3× the median of the others are named as flank wells in the message. A streak (M0 `streak_5x4`, P-3 receives 1.59) does not trigger the gate because every injector row stays ≤ 1; both aquifer cases do (M0: ratio 1.43; external: injector rows 1.78/1.79 with ratio 0.76 — that field has a net injection deficit *and* an aquifer).
- **M1 · §16 — External fixture set vendored.** `New CRM/synthetic_fixtures` (independently generated) is copied to `waterflood_app/validation/external_fixtures/` and frozen. Conventions that differ from the M0 suite and had to be handled: rates are surface volumes with B_o = 1.25 / B_w = 1.02 (the loader converts, §6); its `tau_days` are in *time steps* (its forward model uses Δt = 1), so τ is compared after multiplying by the mean month length; its BHP term is −J·Δp·e rather than the Sayarpour (1−e)·Jτ·Δp/Δt — the two differ only by a rescaling of J, which the fit absorbs.
- **M1 · §16 — External `converted_wells` phase-B tolerance not met and not pursued.** The fixture asks for phase-B f_ij within 15 %; with 48 steps, 4 injectors (two of which only inject from the conversion month) and 3 % noise the fit reaches the noise floor (SSE ≈ 2 800 (m³/d)² ≈ 3 % of signal) with f_ij still non-unique (errors up to 100 % on 0.1–0.5 pairs). The fixture's own verifier skips this case. The test asserts well types, the window split at 2020-01, blind R² > 0.8 and τ within 60 %; pair-level recovery there is a known limitation, not a solver bug.
- **M1 · §9 — Aquifer variant recognised, fitted in Milestone 2.** The prompt's M1 acceptance says the tournament "selects the expected variant" on all fixtures, and both aquifer fixtures expect CRMPA, which the build order places in M2. In M1 the tournament recognises the signature (SUM_F_HIGH), marks CRM-Aquifer eligible and recommended (VARIANT_NOT_AVAILABLE, info) and uses the best available model meanwhile; the test asserts exactly that.
- **M1 · §9 — BLIND_FIT_POOR per producer needs both a poor MAPE (> 15 %) and R² < 0.5.** Per-producer blind R² alone is misleading when the held-out window is flat (noise ≈ signal variance — the external README says the same), and it was dragging the badge to LOW on fields with pooled blind R² > 0.93. The badge uses the pooled field blind R².
- **M1 · §6 — Free gas is only assessed when gas PVT (R_s or B_g, or a table) is given.** With the default PVT() any gas column would flag GOR > R_s = 0 on every step.
- **M1 · §5 — Conversion month.** A month with both production and injection (mode B) is the conversion date when the role changes after it; the B step belongs to both role entities (`P-5@P` ends and `P-5@I` starts on that month).
- **M1 · §7 — O_d per sector on the external `sectored_60`.** 96 steps / (15 + 1) = 6.0 fails "O_d > 6" by definition; the warning is correct and reported; the field still fits with blind R² 0.96 per sector.
- **M1 · prompt §2 — Line length raised to 120** (formatting only), and `N803/N806` disabled: J, F, A, S, X are the Atlas symbols.
- **M1 · §19 — `engine.run_engine` is the L1→L3 driver** (well types → grid → clean → pressure → windows → sectors → gates → tournament → oil cut) and is what the API (M3) will wrap. Sector fits run in parallel with joblib processes.

## Milestone 2 — extended models, optimization, workflow (2026-09-03)

- **M2 · §16 — Optimizer truth in the M0 suite re-frozen (generator 1.1.0).** The M0 generator counted the last historical month as the first horizon step (its recursion returns q_last as step 0) and dropped the 24th future month. Corrected: the horizon is the 24 responding months after the last state. Only the `optimizer` block of each `truth.json` changed (streak: gain vs equal split 6.35 % → 6.98 %, vs hold 4.55 % → 5.05 %); the Parquet rate tables and every other truth field are byte-identical, so the immutability test still passes. The engine reproduces the corrected truth to 0.02 %.
- **M2 · §12 — Objective and base definitions.** "Hold current" is the last set-point (`optimize.current_months: 1`); "proportional / equal split" is the same total water spread equally; bounds default to 0 … 2 × mean current rate per injector; forecast liquid continues the fitted recursion from the last historical state; oil uses the fitted WOR–CWI power law with a fitted pre-history offset C₀ (the log-linear fit was exact only with it). Water-cut ceiling and VRR band are off unless the user sets them; a constraint the base already violates is relaxed to the base level and noted, so the optimizer is never infeasible at hold-current.
- **M2 · §12 — Solver.** SLSQP with finite-difference gradients on the posture-aggregated objective, multi-start from hold-current, equal split, a greedy vertex start ordered by marginal value, and Dirichlet draws; a tighter polish from the best point. The greedy start was needed: SLSQP alone stopped 0.3 points short of the bound-constrained optimum. Forecasts are cached per decision vector.
- **M2 · §13 — Robust posture as constraints.** "Never loses oil in any realization" is one inequality per ensemble member (objective(plan) ≥ objective(hold-current)); if the best feasible plan still loses in a member, hold-current is kept and noted. The P10 statistic uses `np.percentile` over members (with a single member it is that member's value).
- **M2 · §9 / Atlas CRM–Aquifer — CRMPA parameterisation.** The Fetkovich tank reduces to one linear ODE in the influx driven by the field imbalance: dẆ_e/dt = −k₁Ẇ_e − k₂(I − Q). Rates identify (Ẇ_e(0), k₁, k₂) and the per-producer allocation a_j (fitted as an extra injector column); J_aq, c_tV_aq and c_tV_r need a pressure scale, taken from static surveys via c_tV_r Δp̄_r = Σ(Ẇ_e + I − Q)Δt; without surveys the pore volumes are reported as not resolvable (§8 "static surveys validate CRMPA pore volume"). The outer loop uses VarPro-only inner fits with a quadratic penalty on injector rows > 1 (so the deficit must go to the aquifer, otherwise Ẇ_e is unidentifiable) and a Nelder–Mead on log parameters. On `aquifer_6x9`: influx 5 331 → 3 097 vs truth 5 600 → 3 287, allocations within 0.01, f_ij within 6 %, blind R² 0.9998; c_tV_r within a factor 1.6 (the survey-scale regression is approximate).
- **M2 · §9 — Static surveys are collected from any well.** The M0 aquifer surveys are tagged to a pseudo-well "FIELD"; pressure prep previously kept static rows only for producers and dropped them. Now any row whose source classifies as static is kept for CRMPA.
- **M2 · §9 — Two-phase and crossflow variants are implemented but only exercised on synthetic unit cases.** No fixture is eligible (all have mean water cut > 0.5; none has ≥ 4 events/well). Two-phase needs a Corey rel-perm curve passed to `run_engine(relperm=…)`; crossflow uses the CRMP allocation as fixed weights and fits c_tV, J, p̄(0) per tank and X on nearest-neighbour edges. The Olenchikov formulation's replacement of allocation weights by productivity coefficients is applied to the inflow side only (injection still enters through weights) — a simplification, recorded here.
- **M2 · Atlas MPI — influence function.** The closed-rectangle line-source series (Valkó et al. 2000) is evaluated with y arguments ordered (y_D ≥ y_wD), which the formula assumes; the prior is the |J_ij| coupling normalised per injector, blended (geometric mean) with the sector's fitted ln f–distance trend and scaled to the median fitted row sum (§11). Unit constants (α₁, k, h, μ, B) cancel in the prior.
- **M2 · §10 — Rolling windows and CUSUM.** 36-month windows, 6-month step, breaks at events; latest window blended with the full fit by blind-R² weights. CUSUM per pair on f_ij(t)/f_ij(t₀) in units of the median multi-start spread (floored at 5 %), k = 0.5, alarm at 2× spread persisting 2 windows; τ per producer likewise. No fixture shows a shift (they are stationary by construction); the detector is tested on a synthetic doubling.
- **M2 · §3 — Workflow policy.** `workflow.separation_policy: log` records `approved_by_originator`; `enforce` blocks. LOW confidence requires an approver override reason. Approval freezes (data hash, config hash, model version, rates, badge) into a digest; edits after approval create a new DRAFT.
- **M2 · §15 — Rules table implemented literally** in `workflow/scheduler.py`; the "parameters shifted" input comes from the rolling re-fit and decides whether a new DRAFT is opened. Quarterly = 90 days since the last full tournament.
- **M2 · §18 — Store.** SQLite (`store.sqlite`) + Parquet snapshots under `snapshots/<data hash>/`; a re-load with identical content is the same snapshot. Postgres is a deployment swap (M5). Code version = `git rev-parse --short HEAD`.
- **M2 · §12 — Economics sign.** On the M0 fixtures (water cut ≈ 99 %) NPV at $70/bbl is negative: water handling and injection costs exceed oil revenue. The objective still ranks plans correctly; the test asserts monotonicity in price rather than a positive NPV.
- **M2 · §9 / §16 — External `aquifer_9x9`: the fixture's expected winner (CRMPA) is not the composite winner.** CRMPA is fitted (influx 3 258 → 3 122 vs truth 3 500 → 2 400; allocations concentrate on P-1/P-2 instead of P-1..P-3) and has the best blind R² (0.869 vs CRMP 0.850), but the composite score ranks CRMP first by ≈ 0.01: AICc (12 extra parameters) and runtime outweigh a +0.02 blind-R² gain. The weights (`tournament.weights`) were not tuned to the fixture; the test asserts the aquifer variant is fitted, ranks in the top 2 and has the best blind R². The M0 aquifer case, whose influx is ≈ 40 % of injection rather than ≈ 25 %, is won by CRMPA outright.
